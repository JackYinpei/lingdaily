# 实施与验收计划

状态：已有 A/B 真实 Gemini HTTP 体验版，见 [10 AI 接入说明](10-ai-integration.md)。用户已选择先完成“新闻/场景 → 语音练习 → 历史与生词”的核心闭环，播客和进度后置；当前本机开发连接不等于正式认证、Live 音频和云同步阶段已经完成。

## P0 验证基础条件

目标：在大规模写页面前确认系统兼容、身份、音频和数据语义。

| 任务 | 交付物 | 完成证据 |
| --- | --- | --- |
| iOS 15 依赖与工具链 | 固定 Xcode/Swift/SDK 清单；第三方包候选版本 | deployment target 15.0 的构建；明确可用真机/运行环境 |
| 账号映射审计 | 邮箱、Google、Linux.do 三类账号的合成测试样例和映射方案 | 新旧入口使用同一 owner；无法证明归属的情况有处理路径 |
| 认证适配验证 | 单个私有 API 的 Bearer + 原 Cookie 行为 | 有效/过期/伪造/跨项目 Token 与跨账号访问测试 |
| Live 协议验证 | 可用 Token/API 版本、模型、setup 和事件样例 | 真机首段 AI 音频、转录、打断、断线、工具回执全部观察到 |
| 历史语言审计 | 新消息语言 metadata 方案与旧消息 unknown 策略 | 同主题换语言不会带入错误上下文或覆盖历史 |
| API 基线 | 关键 DTO、错误和分页合成 fixtures | iOS 解码和服务端响应使用同一预期样例 |

通过条件：记录可复现步骤与实际限制。工具链不能运行 iOS 15 时，需要补充可用设备或环境；“较新模拟器编译成功”不能算完成最低系统运行验证。生产只读核查应使用授权访问，不将真实账号数据写入测试。

## P1 设计基础与账号

建立 App 依赖装配、NavigationView/TabView、语义色与组件状态预览、三语文案框架、APIClient、错误映射、Keychain 和账号状态。完成邮箱登录/退出、注册确认和恢复账号的明确路径，再逐个增加已经验证的第三方入口。

验收：深浅色、大字体、小屏可用；冷启动恢复会话；刷新请求不并发循环；退出后页面和异步结果不泄露上个账号内容；取消登录能返回原浏览流程。

## P2 选择内容并开始练习

接入新闻 RSS、系统场景、主题详情和语言偏好。实现 AI 数据说明、麦克风授权、开始/取消连接、实时转录、静音、文字输入和结束练习。复用服务端规则，处理不可信新闻/场景内容。

验收：从安装后首次启动到完成一次真实语音练习；首次 AI 回复可听、转录可读、静音与播放独立；断网/拒绝权限/来电/切后台均能恢复到明确状态。内部阶段优先系统场景，公开用户场景进入 App 前必须完成内容治理方案。

## P3 历史与学习项闭环

实现 finalized 消息本地持久化、串行保存、409 合并、历史浏览和续聊、学习项列表与工具保存、退出与删除流程。学习项 API 完成 clientEventId 幂等扩展后开启自动重试；为新消息写入语言/练习尝试 metadata。

验收：Web 与 iOS 读取同一账号数据；服务端成功但客户端超时后重试不重复记词；重启仍能处理待同步；同一主题并发练习保留真实用户消息；账号切换不会重放旧队列；旧消息 unknown 仍可读。

P1–P3 是首版核心功能边界。完成后先进行内部真机验证和小规模 TestFlight；对外测试前完成下面的隐私、账号和内容条件。

## P4 播客与进度

接入节目列表、文稿、播放器，验证与实时语音的音频资源切换，再增加后台播放与锁屏控制。进度展示现有轮次、活跃天和 streak；词汇显示收集量。离线音频、复习算法和学习时长作为独立需求。

验收：耳机拔出、来电、锁屏、音频 URL 失效等场景有正确状态；进度与网页在相同时区和数据集下相符；未新增统计模型前不展示虚构掌握率。

## 功能验收矩阵

| 范围 | 自动化重点 | 人工/真机重点 |
| --- | --- | --- |
| 认证 | Token 验证、刷新合并、过期、owner 隔离 | 系统登录回调、密码管理器、重新安装/退出 |
| 网络与 DTO | XML/JSON、null、未知字段、时间精度、分页 | Wi-Fi/蜂窝切换、延迟与丢包 |
| 音频 | 状态转换、generation 取消、队列上限 | iOS 15 与较新系统；扬声器/有线/蓝牙；回声、来电 |
| 历史 | final 合并、409、重复响应、迟到写入、文件版本 | 两端同时修改、强制关闭后恢复 |
| 学习项 | 参数校验、工具回执、幂等事件 | 空 items、失败后重试、跨语言筛选 |
| 设计 | 有意义的关键 UI 流程 | 深浅色、Dynamic Type、VoiceOver、三语长文案 |
| 服务端兼容 | 原 Cookie 路由、新 Bearer 路由、权限回归 | 旧网页版核心流程 |

改动音频、历史、播客和 SQL 时，执行根 AGENTS 对应测试；提交/发布前执行 `npm run check`。新增 iOS 功能使用 XCTest/XCUITest 和模拟器构建；签名与真机发布是另一条验证路径。

初期文档验收包括事实抽查、内部链接、JSON 样例和文档间一致性。后续 AI 体验版另有 Swift 状态/文件测试、Gemini HTTP 实测与模拟器构建记录，见 10；不得以这些结果冒充真实 Live、账号或云同步验收。

## 发布前必须考虑

| 项目 | 对本产品的实际要求 |
| --- | --- |
| 账号生命周期 | App 内发起账号删除；确认所有 owner 数据、会话和备份处理，不只清本地 |
| 登录选项 | 启用第三方主账号登录时核查规则 4.8；优先评估 Apple 登录，处理隐藏邮箱与账号绑定 |
| AI 数据 | 清楚说明语音、转录和上下文去向并取得相应授权；隐私政策、权限文案和实际服务一致 |
| 公共内容 | 若显示用户公开场景，要有举报、屏蔽、审核和反馈联系方式；第一版可先用系统/私有内容 |
| 数字付费 | 确认订阅权益、恢复购买、到期/退款；按发行地区核查 App Store 支付要求，另立支付设计 |
| 资源授权 | 核查新闻、图片、播客和音色使用范围；保留新闻出处 |
| 数据留存 | 定义原始音频、转录、本地草稿、日志、第三方处理的各自保留期与删除行为 |
| 发布配置 | 确定 Bundle ID、签名团队、开发/测试/生产环境；测试包不连接生产写入端 |
| 运行地区 | 验证目标地区网络和供应商可用性；确定目标年龄与发行地区后再核查适用要求 |

账号、登录、AI 数据、用户内容和支付相关要求参考 [Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/)，提交前再次核对。这里是产品待办，不代表已经完成合规审核。

## 观测、预算与回退

记录匿名化的请求 ID、App 版本、接口/模型版本、连接耗时、第一段音频耗时、错误类别、保存失败率和队列长度。默认不记录密码、Token、完整 WebSocket URL、转录或音频；排查需要样例时使用合成数据或明确授权的短期采集。

为 Token 签发和场景生成设置用户级限制、日预算和异常告警。记录供应商费用与有效练习量，使用真实数据确定免费额度和付费权益。具体性能目标在 P0 获得基线后确定，不能把未测的秒数写成保证。

服务端先部署向后兼容能力，再发布客户端。每个新增能力可独立关闭，关闭时 App 显示清晰的暂不可用状态。数据库采用增量迁移；App 降级不能要求删除用户数据。发布记录包含版本、迁移状态、已知限制和回退方法。

## 仍需产品确认

首发市场与语言优先级、第三方登录组合、是否包含用户公开场景、是否首发收费、隐私保留期。可以继续完成基础设计和验证，在依赖这些决策的功能之前再明确。
