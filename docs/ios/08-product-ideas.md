# 产品创意：让用户有理由开口、回来和付费

状态：创意提案，2026-09-29。A/B 已从交互原型升级为真实 AI 体验版，见 [10 AI 接入说明](10-ai-integration.md)；其余功能仍待挑选。以下商业判断、留存判断和优先级均是假设；未进行用户访谈、留存实验或付费验证。

## 建议先抓住的人群与价值

建议优先研究“能看懂一点，但遇到真实沟通就卡住”的成人学习者，尤其是有出差、旅行、面试或跨语言协作需求的人。这个用户定位尚未确认，先用访谈和行为验证，避免同时做零基础课、考试提分、儿童游戏和职业教练。

可以尝试的产品表达：**把明天想说的话，今天先说顺。** 每次练习帮助用户完成一件事，结束时留下一句能带走的表达；下一次练习再让它自然出现。

现有新闻提供新鲜素材，场景提供练习目标，转录和学习项提供个人线索。把它们连成连续体验，可能比持续增加一个新的聊天入口更有价值。这是产品判断，不是已经证实的市场空白。

## A. 一句话重来

场景：用户说到“这个安排对我不太方便”就改说中文，导师给出一种地道表达。纠错卡下面出现“我再说一次”，用户可以马上重说；导师继续扮演原角色，用不同问法接下一句。

交互原型：原话 → 简短建议 → 三种支持程度（中文意图 / 关键词 / 完整例句）→ 用户重说 → 继续原场景。第一次提供帮助，下一次逐步收起提示。用户可选“练完再反馈”，避免每句话都被打断。

吸引点是可感知的进步，付费假设是反复练自己的表达问题。**基础纠错和查看自己的历史保持可用**；付费可提供针对弱点编排的完整训练，而非在用户最尴尬的时候弹付款。

最小试验：挑 10 个常见“中文能表达、英文卡住”的意图，用手工校对的建议演示；看用户是否愿意主动重说，以及提示收起后能否说出等价意思。比较“只显示纠错卡”和“带重说入口”的表现。

工程影响：同一会话内增加重试状态和 attempt 标记即可先验证。不能把新说法覆盖原消息；若提供原音频 A/B 回放，需要额外的短期录音授权、存储与删除设计。当前数据库并未保存 correction，跨天复练要另定义哪些学习证据被保存。

## B. 明日预演

场景：用户输入“明天要向同事解释项目延期，希望争取两天时间”。App 只补问三个必要信息：对方是谁、希望得到什么结果、有什么限制。随后进行一段简短排练。

第一遍对方耐心，第二遍对方会追问或提出限制；结束后给出“开场一句、关键解释、请求一句”的随身卡。第二天可以再练 60 秒，而不是重新描述整个背景。

可用的新场景：旅行订房出错、跨时区会议争取资源、面试解释职业转向、与房东协商维修、跟客户确认模糊需求。表达训练不承诺面试录取或谈判结果。

留存来自用户不断出现的新任务；付费假设来自具体用途和时间压力。候选商业形式是专题训练包或订阅内的个人预演额度，先观察哪种任务有人重复使用。

最小试验：招募有近期真实任务的用户，用手工编排的 3 轮排练验证。记录开始前目标、结束后是否愿意再练、真实事件后哪些表达用上了，以及是否愿意为下一次任务付费。不能只问“你觉得有用吗”。

工程影响：复用场景生成与 Live，增加 goal、constraints 和 outcome rubric。先提示用户去除公司机密和个人隐私，外部材料只作为参考内容；不自动导入邮件/日历。

## C. 今日身份：新闻变成任务

同一条公开新闻，不只是“你怎么看”，而是提供三个可选角色。例如：一座城市拟调整公共交通时刻表，用户可以扮演通勤者、记者或社区发言人。

任务示例：先用 20 秒说明变化，再问两个澄清问题，最后提出一个有理由的建议。导师用对方角色回应，结束卡只评价是否表达清楚、是否完成沟通目标，不评价用户立场是否“正确”。

交互：先选角色卡，再看到一个具体目标；练习中可展开已核实的事实卡和出处。事实与虚构角色对话分开标注，不能把模型编造的背景包装成新闻。

留存假设是每日素材更新且练习短；付费假设是职业/兴趣主题包、不同沟通难度和多次个性化挑战。当前新闻抓取是素材基础，不等于已经具备编辑质量。

最小试验：人工选 5 条适合讨论、事实可核实的新闻，每条写 3 个角色任务，与普通自由聊天比较开始率、完成率和自愿再选一个角色的比例。只有选择性真实回访才支持日更投入。

工程影响：先用编辑过的 scenario 模板引用新闻快照与来源；增加 contentVersion 与时效标记。规模化日更前再建设内容审查和失败降级，不让空新闻触发凭空写作。

## D. 连续故事：出差 72 小时

故事可以是“你第一次独自出国参加一个小型展会”。每章 3–5 分钟，有一个能说清楚的目标；错误可以带来另一种推进方式，不直接终止学习。

| 章节 | 情境 | 用户需要做到 | 后续影响 |
| --- | --- | --- | --- |
| 1：到达 | 行李未出现 | 描述行李，询问下一步和联系方法 | 拿到取件方案或需在酒店等待 |
| 2：入住 | 房间与预订不一致 | 解释问题，礼貌提出可接受替代 | 获得安静房间或早餐补偿 |
| 3：开场 | 展会认识新同事 | 自我介绍并问一个跟进问题 | 解锁下一位联系人 |
| 后续：提案 | 临时收到邀请 | 说明想法、应对质疑、约定下一步 | 形成不同结局 |

可替换的故事季：东京周末的失物寻找、社区咖啡馆的第一周、轻科幻“空间站误点广播”。先做生活场景验证；悬疑和科幻的词汇/信息负担更高，属于之后的内容实验。

交互：简洁章节地图、角色卡、一个当前目标和可展开线索。说话会推进剧情；点击按钮只选意图或使用提示。已经完成的目标不会因为模型遗忘而反复要求用户重做。

留存假设是角色与故事有连续性；付费假设是完整故事季和不同难度的重玩。不要先投入大量 3D、美术或实时多角色 Agent。首个试验可由一份场景状态图和一个模型依次扮演不同角色完成。

最小试验：只写三章，每章最多两种有效推进方式。观察用户是否在没有推送催促时主动进入下一章，并能说明上一章练过的表达。若只喜欢剧情、不愿开口，调整目标和交互，再考虑停止。

工程影响：故事模板有版本、章节状态由确定规则维护，模型输出只是候选动作；服务端校验后推进。故事结局、学习反馈和商业权益独立保存。现有 scenarios 的一条 prompt 不能承担完整剧情进度。

## E. 三个词回来找你

昨天用户在酒店场景卡在“availability”。今天的会议预演出现需要询问空闲时间的机会；导师不先给答案，等用户尝试表达，再给适当帮助。

每次最多选择少量、确实有过困难的项目，用户可排除已会或不想学的内容。完成时用“这次你主动用出了……”展示证据；一次成功不自动等同掌握。

留存和付费假设是长期训练的连续性。最小试验比较同一批用户的原场景重练与换场景使用，观察脱离提示后的主动使用。竞品已有弱点练习，特色要落在我们的任务衔接与反馈质量上。

工程影响：现有学习项是事件数组，需要明确 canonical item、复习尝试、提示程度和判定证据。先用少量人工挑选项目试验，再设计复习算法与规范表。

## F. 突发状况牌

用户已经会点咖啡，但这次店员说“没有燕麦奶了”；已经会入住，但前台找不到预订。界面弹出可选“给我一点变化”，下一轮发生一次合理的小意外。

可调支持级别为“慢一点 / 正常 / 有点挑战”。不靠让导师更凶来制造困难，控制的是语速、信息量、追问和可用提示。慢速选项要验证模型和播放策略是否真的支持。

留存假设是同一技能可以迁移到变化情境；付费可以归入职业/旅行进阶包。先手写 12 张可插入的意外卡，验证是否提高主动重玩，而不是让新手退出。

工程影响：增加受控 scenario event 和目标状态；与 B/D 共用。随机性需要可复现 seed/内容版本，方便排查跑题和不合理难度。

## G. 今天我来当主持

用户当记者、播客嘉宾主持或项目负责人，主动决定问什么。AI 只给一张嘉宾背景卡，在对话中留下可以追问的线索；结尾反馈“你问出了什么”和“哪里可以继续追问”。

复用现有新闻和双主播播客素材，可先做“听 30 秒 → 你采访一位虚构嘉宾”。所有角色明确为虚构，不冒充真实新闻人物或提供未经授权的名人音色。

留存假设是表达方式从被动回答转为主动组织；付费假设是面向主持、面试官、跨国团队负责人等具体任务。最小试验先比较用户愿意主动问几个问题、是否愿意继续下一主题，不用自动发布音频。

工程影响：新的对话目标与提示策略即可做原型；录制成个人节目、分享、音色和音乐是独立后续范围。

## H. 这周我真的会说了

每周给用户三条有出处的变化：“周一靠关键词表达的请求，周五在新场景中独立说出来了。”可以进入当时的练习片段，重试同一个沟通目标。

不先做神秘的“口语 92 分”。反馈来自明确 rubric 和消息证据，例如是否提出请求、解释理由、澄清误解；不能仅用转录准确度推断发音，也不把模型判断包装成正式考试等级。

留存假设是可见的成长；付费假设是连续训练档案和定向练习。最小试验人工生成第一份周报，观察用户是否接受评价、是否据此开始下一次练习。分享默认关闭，分享卡由用户预览并去除私人内容。

工程影响：要建立可追踪的练习尝试、评分规则版本和证据引用。跨周原音频对照需额外授权和保存期，基础方案可只比较文本与任务完成情况。

## 新交互怎样进入现有 App

先保留已经规划的“练习 / 学习 / 我的”，在练习首页放一个“今天要练什么”任务入口和现有新闻/场景入口。A 的重说按钮属于纠错卡；B/C/D 是主题详情模板的不同内容；E/H 放在练习结束与学习页。避免每个创意都新增一个 Tab。

通用一次体验：明确目标 → 选择提示强度 → 真实开口 → 有证据的简短反馈 → 自愿重试/下一次任务。奖励优先用可带走的表达和真实目标完成，连续天数只做温和提醒。

## 先怎样验证

推荐顺序是 A/B 的小规模辅助测试 → C 的日更内容试验 → D 的三章试验。A/B 现已有原生本地原型供体验，尚未运行正式用户实验；C/D 继续先用手工内容做小规模验证。

| 实验 | 需要观察的行为 | 不成立的迹象 |
| --- | --- | --- |
| A 重说 | 用户主动点击重说，提示减少后仍能表达意图 | 只读例句，不愿再次开口 |
| B 预演 | 有真实任务的人完成练习，并为下一次任务再次回来 | 只觉得好玩，任务发生前也不再练 |
| C 今日身份 | 选择任务、完成沟通目标、隔日自愿回来 | 新闻阅读吸引人，但角色任务无人开始 |
| D 三章故事 | 自主进入下一章并保留学习目标 | 只点剧情，不说话；制作内容成本持续过高 |

每轮可先邀请 8–12 位目标用户找出问题，这个规模适合定性学习，不足以证明市场转化率。A/B 的大样本指标和停止阈值应在获得基线后预先确定；按任务、水平和语言分组，避免把所有学习者平均成一个数字。

指标建议：首次有效练习完成、每周至少两天完成目标的用户比例、主动再练率、下一次任务返回率、每次完成的模型成本、在明确价格下的真实购买/续费。点击价格按钮只代表意向，不能算收入；小样本口头反馈不能当 PMF 证明。

## 收费怎么试

基础体验应允许完成一次真实任务并看到自己的结果。候选付费权益：更多预演次数、完整专题/故事、个人弱点练习和持续复盘。先择一种主模式验证：持续日常价值适合订阅，明确短期任务适合专题包；二者都要明确次数/时长限制和失败补偿。

暂不定正式价格，也不许诺无限实时语音。先记录成本，再展示真实、清楚的候选权益和价格进行验证；实际收费前完成商店支付、恢复购买、退款与服务端权益校验。

每位付费用户的粗略贡献 = 实际到账收入 − 模型/音频可变费用 − 存储/传输增量费用 − 增量服务成本。固定研发和获客费用另算。要看高用量用户的成本分布，不能只用平均一次聊天费用推算盈利。

完整任务结束后或用户主动选择额外训练时展示付费方案；不要中途打断正在进行的练习。失败连接和系统错误不应消耗有效练习权益。

## 架构与数据影响

只有选中的创意才进一步设计数据库。可复用的长期方向是：内容定义与用户进度分离，练习尝试与累计历史分离，权益与模型会话分离。

| 候选实体 | 用于什么 | 第一轮创意评审是否需要建表 |
| --- | --- | --- |
| practice run / attempt | 一次练习、重说、分支、目标与证据 | 否；先用规格/合成样例验证 |
| mission / story definition | 已编辑内容、章节、目标、版本 | 否；先写三章内容草案 |
| story progress | 用户章节状态、已达成目标 | 选定 D 后需要 |
| review attempt | 学习项在不同场景的使用与提示程度 | 选定 E/H 后需要 |
| entitlement / usage ledger | 购买权益、消费、失败返还、供应商对账 | 决定收费方案后需要 |

这些都是未来概念，不是现有 schema。涉及跨设备分支时不能继续只依赖 `(user_id,news_key)` 表达每次尝试，应按 ADR 做增量迁移，同时保留旧历史入口。

## 当前建议

先把可靠的核心闭环做出来。创意验证优先选 **A“一句话重来”** 和 **B“明日预演”**：它们与现有纠错、场景、学习项最接近，也能较快观察用户是否愿意再次开口和为具体任务投入。**C“今日身份”** 作为 LingDaily 新闻特色的候选主入口；**D“出差 72 小时”** 用小规模内容试验验证故事吸引力后再决定投入。
