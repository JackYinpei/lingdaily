# LingDaily iOS 重构方案

状态：重构方案 + 真实 AI 体验版 0.3.0（界面重做）。更新：2026-09-30。

本次范围是为现有 `talk-news` 增加原生 iOS 客户端，最低支持 **iOS 15.0**。Xcode 工程已有免登录的真实 Gemini 体验版，通过本机开发服务连接，具体实现以 [10 AI 接入说明](10-ai-integration.md) 为准。正式账号、云同步和数据库新增项仍是后续计划。

## 建议路线

采用 **SwiftUI 原生界面 + 现有 Next.js 服务端 + 现有 Supabase 数据库**。网页和 iOS 共享账号、内容、业务规则和数据；界面、导航、音频采集与播放分别实现。

用户已选择先完成“选择新闻或场景 → 语音练习 → 保存对话 → 查看历史和学习项”的完整流程，再补播客、进度和场景创作。管理后台、播客生成和 SEO 首页继续由服务端/网页承担。

架构从一个 App target、按功能组织的代码和少量外部服务接口开始。界面、状态、数据访问有清楚边界即可；增加独立模块、框架或多个开发 Agent，要有具体的复用、测试或协作需求。

## 已知的关键约束

1. **iOS 15 是硬要求。** `NavigationStack`、Observation、SwiftData 等不能直接成为全量用户的基础依赖；依赖包也要核查最低系统版本。
2. **原生认证需要服务端适配。** 当前私有 API 调用 `auth()` 读取 NextAuth 会话，没有通用的 Supabase Bearer Token 入口。
3. **语音协议需要先验证。** 本地 Gemini 代码使用 `v1alpha`；本次读取的官方临时 Token 文档使用 `v1beta`。需要一起验证 Token、WebSocket、模型和事件格式，不能仅替换版本字符串。
4. **现有数据必须可继续读取。** `news_key`、复合游标、`revision`、历史兼容表和生产迁移边界都要保留。
5. **语言切换是一个数据设计问题。** 当前对话唯一键不包含语言对，不能假设同一新闻在不同学习语言下已经隔离。

这些结论分别来自本地代码核查和官方文档核查，详细证据见各专题。未连接生产数据库或测试生产登录；Gemini HTTP 已在本机实际验证，Gemini Live 尚未验证。

## 暂定决策与仍需选择的事项

| 事项 | 本方案建议 | 状态 |
| --- | --- | --- |
| 客户端 | 原生 SwiftUI；iPhone 优先，兼顾现有模板的 iPad target | 建议采用 |
| 最低系统 | iOS 15.0 | 用户已确定 |
| 后端 | 保留 Next.js，逐项提取公共业务服务 | 建议采用 |
| 认证 | Supabase 身份 + 服务端 Bearer 校验；旧 Web Cookie 登录继续兼容 | 待验证账号映射 |
| 本地数据 | Keychain 保存凭据；文件保存待同步对话；小设置用 UserDefaults | 建议采用 |
| 首版范围 | 先核心练习闭环，再补播客与进度 | 用户已确定 |
| 登录入口 | 邮箱先打通；第三方入口逐个验证；上架前决定 Apple 登录 | 待账号审计与产品选择 |
| 历史语言隔离 | 先审计数据，再决定有版本的身份迁移；避免改变已有 key | 待专项决策 |
| 对外发布 | 先内部真机验证，再 TestFlight，再 App Store | 建议采用 |
| 市场与收费 | 发行地区、目标年龄、收费模式 | 待产品确认，不阻碍写方案 |

产品创意单独供用户挑选；A/B 已做成真实 AI 体验版，其余创意尚未加入核心功能排期。

## 本轮交付边界

初期交付了 01–08 文档及模板，随后交付 09 的本地原型；用户明确要求真实 AI 后，增加了受本机配对保护的开发 API 和原生 AI 流程，见 10。未修改现有 Web 路由、数据库迁移或生产环境。正式认证、同步与 Live 接入仍按 [阶段 P0](05-delivery-plan.md#p0-验证基础条件) 推进，体验版不等于 P0–P3 已完成。
